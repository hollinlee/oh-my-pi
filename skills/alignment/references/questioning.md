# Questioning

## 目标

用少量高价值问题帮助用户想清楚，而不是用问题轰炸用户。

## 规则

- 一次只问一个问题。
- 问题必须推进决策树，不问装饰性问题。
- 每个问题都给推荐答案、默认取舍或选项。
- 如果用户已经隐含回答，不要重复问。
- 如果问题能通过读取 repo 回答，优先读取相关文件。
- 用户说“够了”“总结”“先这样”时，停止追问并输出 brief。

## 好问题类型

- 目标：你真正想改变什么？
- 非目标：这次明确不做什么？
- 约束：必须保留什么？不能破坏什么？
- 取舍：如果 A 和 B 冲突，优先哪个？
- 验收：什么结果算完成？
- 风险：失败时最可能坏在哪里？
- 受众：这个能力主要服务谁？

## 问法

推荐格式：

```txt
我先确认一个关键点：...

我的默认建议是 ...，理由是 ...。
你想按这个默认走，还是改成 ...？
```
