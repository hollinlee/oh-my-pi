# Product Tech

## Use when

适合 SaaS、developer tools、数据产品、AI 工具、技术文档入口，以及以 projects 和工程能力为核心的个人网站。

## Avoid when

主题需要文化叙事、温暖照护或感官奢华时，不要把所有内容转换成 dashboard 和 metrics。

## Typography

使用清晰 sans 处理界面和正文，mono 只用于代码、数据、状态与真实技术语义。通过紧凑 utility hierarchy 和稳定数字宽度提高扫描效率。

## Palette character

以高可读中性色为底，使用一个产品信号色和明确 semantic colors。Dark mode 不是默认要求，neon 也不等于技术感。

## Layout and hierarchy

围绕用户任务、对象关系和状态组织界面。导航、command、table、chart 和 detail panel 应反映产品模型；marketing page 也应展示真实产品行为。

## Surface and depth

使用少量层级 surface、清楚 border 和状态差异。卡片只用于真实独立对象；避免 card-border-shadow 高密度重复。

## Motion

优先状态 transition、数据更新、command feedback 和一个产品 demo 时刻。避免每个 section 的通用 scroll reveal。

## Signature candidates

可选择一个真实可操作 demo、主题化 command palette、项目 dependency map、live status 或与专业领域相关的数据视图。

## Defaults to reject

拒绝深色背景加酸性绿、虚构增长指标、三张 feature card 和终端窗口装饰。用真实 workflow、对象和数据替代。

## Responsive behavior

小屏保留主要任务路径；table 和 dense panel 使用重排、summary/detail 或受控横向滚动，不强行压缩全部列。

## Accessibility risks

状态不能只靠颜色；图表需要文本替代；mono 小字号和低对比 secondary text 容易降低可读性；复杂 keyboard interaction 需可发现。
